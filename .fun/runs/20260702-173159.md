# Run 20260702-173159 — bounded per-feed timeout in feeds.py

## Task
`fetch_all()` in `feeds.py` could hang indefinitely: `feedparser.parse()` fetches
the URL itself with no network timeout, so a slow or unreachable RSS source would
block both startup and `/refresh`. Add a bounded per-feed timeout (~10s) and make
one failing source not prevent the others.

## What changed
- `feeds.py`:
  - New `_fetch(url)` helper: fetches feed bytes via stdlib
    `urllib.request.urlopen(req, timeout=FEED_TIMEOUT)` with a browser-like
    User-Agent, then hands the raw content to `feedparser.parse()`.
  - `FEED_TIMEOUT = 10` (seconds) constant.
  - `fetch_all()` now wraps each source's fetch in try/except; on any exception it
    prints `feeds: skipping <name>: <exc>` and `continue`s to the next source.

## Key decisions
- **Stdlib-first, no new deps.** `feedparser.parse()` accepts already-fetched
  bytes/strings, so the fix is to move the network call to `urllib.request` (which
  supports a `timeout=`) and keep feedparser as the pure parser. No `requests`,
  no threads, no signals.
- **Timeout semantics:** `urlopen(timeout=...)` bounds connect + each socket read,
  which covers the "slow/unreachable" cases the task cares about. Good enough and
  simple; a hostile server dribbling bytes slower-than-timeout-per-read is out of
  scope.
- **Isolation:** per-source try/except means a bad feed is logged and skipped; the
  remaining feeds still populate the DB.

## Verification
- `./.fun/check` → OK. Layer 1 (py_compile) enforced; layer 2 smoke skipped here
  because app deps aren't importable in this environment (expected — no network,
  container has no deps).

## Known dead-ends / not done
- Did not add threading/signal-based timeouts — unnecessary given feedparser
  accepts pre-fetched content.
- Did not make timeout configurable via env; a module constant matches the app's
  simplicity. Easy to revisit if needed.

## Open threads
- None. Behavior is unchanged for healthy feeds; only failure/slow paths differ.
