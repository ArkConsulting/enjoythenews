# Run 20260702-175724 — make DB_PATH cwd-independent

## Task
`db.py` defined `DB_PATH = "enjoythenews.db"` relative to the current working
directory, so the app only worked when uvicorn was started from the repo root —
a documented footgun. Make `DB_PATH` resolve to the same file next to `db.py`
regardless of cwd, without changing where the database actually lives when
started from the root. Flag the now-stale CLAUDE.md constraint in
MEMORY-PROPOSALS.md (CLAUDE.md is off-limits).

## What changed
- `db.py`: `DB_PATH` is now `str(Path(__file__).resolve().parent /
  "enjoythenews.db")` — an absolute path anchored to the module's directory.
  Added `from pathlib import Path` and a short comment. Nothing else touched.
- `MEMORY-PROPOSALS.md`: appended a note flagging the stale "Known constraints"
  bullet (and the matching "Architecture" line) in CLAUDE.md, which still say
  the server must be started from the repo root.

## Key decisions
- `db.py` lives at the repo root, so "next to db.py" IS the repo root — the DB
  file stays exactly where it was (`enjoythenews.db` at root) when launched from
  there. Only the failure mode of launching from a subdirectory is fixed.
- Kept `DB_PATH` a `str` (not a `Path`) to preserve its existing type; `sqlite3`
  accepts either, but callers/tests may assume a string.
- Used `.resolve()` so the stored path is absolute and normalized.
