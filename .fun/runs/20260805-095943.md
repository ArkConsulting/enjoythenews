## What changed
- `main.py`: added an in-process periodic refresh — `_periodic_refresh()`, an
  asyncio task started at startup (reference kept on `app.state` since asyncio
  holds tasks weakly) and cancelled in a new shutdown handler. It sleeps
  `REFRESH_INTERVAL` (hourly), then runs the existing `_do_refresh()` via
  `asyncio.to_thread` so the sync urllib/Anthropic work never blocks the event
  loop; failures are caught and printed, matching `feeds.py`'s style. The
  startup handler became `async def` (behaviorally identical — Starlette called
  the sync version directly in the loop too).
- `MEMORY-PROPOSALS.md`: appended both proposed CLAUDE.md edits — the reworded
  Frontend-pattern bullet ("Full pages are server-rendered Jinja2; new dynamic

  bullet.
- `TODO.md`: both items marked done with pointers to the proposals.

## Key decisions
- **In-process asyncio task over a systemd timer.** Dev and prod behave
  identically with zero server/ops configuration; stdlib-only (~20 lines); a
  timer would fire only in production and would have to curl `/refresh`, which
  renders a full HTML page. Consistent with the no-frameworks philosophy.
- **Sleep-first loop.** The startup refresh already covers "refresh now", and
  sleeping first means the `.fun/check` smoke (which patches `_do_refresh` and
  runs startup via TestClient) never triggers a network fetch. Verified: the
  smoke passes and shuts the task down cleanly.
- **CLAUDE.md untouched.** Both items require CLAUDE.md edits, which runs must
  not make — the exact wordings are proposed in MEMORY-PROPOSALS.md instead.
